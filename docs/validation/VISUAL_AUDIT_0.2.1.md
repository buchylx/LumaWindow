# 0.2.1 视觉复诊：空间层次与光照组织

日期：2026-09-17。诊断对象：提交 `3fc8617`、交付构建 `c3f8e6775dd7194b`。本轮只更新诊断和设计约束，不修改渲染实现。

## 结论

用户认可云山形体比之前更真实，但指出前后云层缺少可感知的色彩和清晰度区别，日月附近也没有合理的局部受光关系。对照后确认：**目前的深度主要表现在位移和遮挡，尚未充分表现在色彩、反差、细节和光照上。** 上轮“有远近颜色角色”不等于画面已经形成足够的层次。

下一步应先把远、中、近景的视觉关系和局部受光建立起来，再细化笔触。无需继续以更密的噪声、更亮的云缘或更多景物层数作为主要改进。

## 1. 近云与远云共享过多明暗范围（最高优先级）

**观察：** 晴昼里桥前桥后的云都偏白亮、阴影都接近同一种蓝；暖霞里底部近云同样铺满奶油亮斑与桃色；月夜近云也有大面积银蓝碎亮区。部分近山已经更深，但云的深度线索明显不足。缩小看时，云容易混成一整片纹理。

**概念稿：** A 的近云有成片紫色云腹，少量边缘接暖光；远处云海更浅、更细、反差更小。C 的前景有能安静托住画面的深色大面，亮处在中远景逐步展开。

**实现：** cloudNearShade / cloudNearBody 虽有压暗，但大部分云层仍共享同一个 light；近景也套用相同的高光混合和 rim 规则。中间几层主要仍使用同一组 body / shade。雾的距离差异不足以替代完整的层次设计。

**调整方向：** 先明确近、中、远三组明暗范围，再沿深度连续插值。近景的暗部更深、体积反差更明确，高光留给局部朝光轮廓；远景减少最亮与最暗之间的跨度，逐步接近天空/空气的颜色。不能只把近云整体乘一个暗色系数，否则受光面也会脏掉。

## 2. “近实远虚”没有覆盖纹理与边缘（最高优先级）

**观察：** 云的内部碎斑在多个深度层里都很显眼；底部近云有密集花纹，背景云也保留类似的碎裂反差。近山内部反而经常是柔糊色块，与相邻清晰云缘的关系不一致。

**实现：** 各云层共用相同 q 频率、grain 权重及明暗阈值；scale 按层指定，却不保证屏幕上的细节按深度递减。轮廓 aa 使用 fwidth，主要解决像素抗锯齿，并没有定义远处形体应如何更柔和。多个山层也使用同一套面内噪声。

**调整方向：** 远处减少高频肌理及其对比，合并小色面，只保留大轮廓和轻微起伏；近处允许清楚的大转折与少量可辨细节。清晰不等于满屏锐化，更不等于增加容易闪动的细线。优先按距离减少细节计算与反差，不先加全屏模糊后处理。

## 3. 有光向，缺少光照在画面中的主次（最高优先级）

**观察：** 暖霞最亮区域仍由云纹理到处散布；太阳附近没有稳定形成明亮、温暖的云海开口，背离太阳的一侧也未充分安静下来。夜景整体偏均匀蓝色，月光没有组织出明确的受光区域。日月能运动，不等于它们已与整个环境建立可信的照明关系。

**实现：** 每层使用相同 lightDirection。云通过两次密度采样之差产生局部明暗，但云山着色没有接收日月位置或统一的局部照度分布；山面受光还混入了与山脊朝向关联较弱的一维噪声。天空有很弱的横向颜色变化，不能说明云山也受到了同一片光照。

**关于“离光源越近越亮”：** 这里应保留用户希望的视觉关系——光源周围有更明亮的受光云面、邻近山脊被照亮、背光面更沉。太阳/月亮在场景尺度上更适合作方向光，不能把它们当近距离灯泡，按与屏幕圆盘的距离把整片山云染亮。背光面、遮挡和厚云仍应保留暗部。

**调整方向：** 把景深和受光分开控制：一条规则负责近实远虚，另一条负责受光方向、受光强弱和暖冷变化。先形成宽而缓的受光区域，再由形体朝向/密度分配到局部色面；可用风格化低成本着色实现，不要求体积光、光束、bloom 或光追。远处朝光云可以比近处背光云亮，近云朝光边也可以局部发亮。

## 4. 山的剪影改善，但仍像大块布景

**观察：** 暖霞抽帧中部与右侧远山形成宽大的紫色实体，晴昼对应大块蓝色；山脚少有逐层消隐。山与山之间的空气缝隙少，顶部起伏更多了，但看进去的纵深仍不足。7021 的近山更深，却以模糊的大色斑表现山面，缺少山肩、沟谷和受光面之间的对应。

**调整方向：** 增加山脚隐入云海的过渡，把跨屏的大山墙拆成前后可读的山脊关系；轮廓、山肩与面内色块采用共同的形体依据。小规模树影可后续补充尺度，不用植被掩盖大形问题。

## 5. 云纹理抢过云团体积，画面缺少安静区域

**观察：** 暖霞底部和月夜近云有重复出现的亮斑、暗洞式纹理，视觉复杂度接近整片均匀铺开。自然形体比旧版更可信，但仍容易先看到“表面花纹”，再看到云团。

**概念稿：** 大云团、次级起伏与边缘细节有明确主次；大面积阴影中并不处处都有强烈的明暗碎斑。

**调整方向：** 让大块云腹、受光面先成立，中尺度团块负责转折，小尺度笔触只出现在适合的位置。远云更节制，近云也必须保留平静大面。保持写意目标，不把“更真实”误解为追求摄影级云雾模拟。

## 6. 桥与列车尚未融入新的空间层次

**观察：** 密集竖条已去掉，应保留这个改进。但桥的连续拱边仍近乎等亮，桥墩大范围完整露出，容易形成抢眼的重复框架。晚霞列车车窗偏灰、车体很细暗，暖光的叙事作用弱于概念稿；远眺比例与水平构图继续保留。

**实现：** 窗光主要由 night 因子驱动，在暖霞阶段仍偏日间玻璃色；桥整体染色为主，对局部环境光的响应较少。

**调整方向：** 收敛拱边反差，让桥墩下部与低云、空气发生渐隐和局部遮挡；晚霞逐渐出现温暖车窗，不等到深夜才有明显变化。先解决自然景物的远近与受光，再协调人工结构，避免再次增加细碎装饰。

## 7. 天空仍有独立背景感

**观察：** 稀薄云带偏横向软涂抹，和积云的碎色面、山的剪影不完全协调。日月与场景已有轨迹联系，天空笔触与局部光照还缺少联系。

**代码可确认的限制：** 薄云和天空合在 renderOrder=-100 的背景里，日月在 -80，故这层薄云不能从日月前面经过。这是层次实现限制；本次没有声称在录像里新观察到一次具体穿帮。

**调整方向：** 后续把少量薄云的前后关系处理清楚，统一笔触尺度与受光色；星点维持稳定、克制，不增加闪烁或粒子特效。

## 下一轮优先顺序及验收

1. **先分清距离**：固定世界位置、固定时段，建立近/中/远的色彩、反差、细节尺度和边缘规则。默认晴天以及雾感为 0 时也能看出层次，不依赖用户把雾拉满。
2. **再组织光照**：同一世界中改变日月相位，光源一侧的受光面与背光区有清楚而连续的变化；不整层一起发白，也不沿屏幕圆盘画光圈。
3. **再改山脚与云团大面**：保留开口、稀疏段、暗部休息区，让山谷能向远处展开。
4. **最后协调桥车与天空**：保留水平古典客车，消除等亮装饰边框感，补上日月与薄云的层次。

验收需要同时看彩色图和灰度明暗关系、同一 seed/位置/取景的晴昼/暖霞/月夜，以及正常速度动态。灰度缩略图应能分辨三层，但不要求近景每个像素都比远景暗。远景柔和不等于失焦；近景清楚不等于高频噪声更密。日月过渡、前景掠过和低画质采样不得引入闪动。

本轮没有改运行代码，版本保持 0.2.1，也不重新打包。下一轮实现以这份诊断为依据，最终视觉判断仍交给用户。
