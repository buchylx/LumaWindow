## 0.1.2 本轮执行结果（2026-09-17）

已重写自然景物主渲染路径，新增 `nature.ts`：云团由种子与连续世界坐标生成，叠加大小轮廓和随形体变化的色面；山脊使用独立的连续高度场。天空薄云也随世界距离移动。旧 `paint.ts`、`composition.ts` 和图集仅留作历史研究，当前场景与发布构建不再引用它们。

铁路为严格水平的模块化拱桥；列车改为十节纤细客车、煤水车及蒸汽机车，补充窗框、腰线、轮组、锅炉箍、烟囱和桥梁拱券等结构。自然景物保持写意的色面，人工结构保持清楚的轮廓。近景使用世界坐标移动，取消固定屏幕两侧的山体。

渲染仍共享网页与 Tauri 生命周期。固定 14 个蒸汽对象，铁路实例有界，当前场景不加载图像纹理；保留三档像素/帧率预算、暂停、状态恢复与释放。减少图集与对象不等于已经证明省电：新的逐像素程序场增加了 GPU 运算，低配实测仍需单独进行。

快速开发验收可运行 `LumaWindow.exe --quick-test`：50 次切换后，执行 60 秒有效活动时间的一分钟昼夜循环，记录 `quick-complete`。`--self-test` 仍是独立的两小时长测入口，不作为每次视觉迭代的等待要求。正常启动默认 30 分钟。

本轮改进已获用户正向认可；**视差、雾感与天空运动等反馈仍待处理，尚未整体结项**。云团笔触的自然程度、地景组织的丰富度、精细主体的最终美术质感仍需根据实际动态反馈继续调整。后续历史章节描述 0.1.1，不作为 0.1.2 的实现清单。

## 1. 当前结论

**保留宿主与平台基础，重写云海场景。** 已有原型证明工程能启动、参数能传递、Windows 能打包，未证明视觉目标或低功耗目标达成。此前围绕云团网格和天空噪声的微调停止作为主路线。

### 已确认的开发策略：视觉先达标，性能同步测量

先证明 A 风格的实际动态效果成立，再根据实测优化并确定设备档位。R1/R2 可暂时超过初始像素、纹理、内存等预算，须记录使用的实验配置、效果收益与资源成本，不因旧预算提前降低云层造型、冷暖和空间层次。实验配置与日常默认档分开，不能把超预算样板当成已完成的低功耗产品。

先优化无用绘制、重复计算、资源复用与透明叠加，再调整清晰度、远景细节和帧率；各档尽量保留主要云形、构图、色彩、列车和完整昼夜。若核心效果仍成本过高，明确展示视觉与资源差异，再决定取舍。2014 年 Mac 是兼容边界探索设备，不决定整体视觉上限；是否支持及可用档位依据实测。

安宁的美术约束、有界对象/缓存、正确释放、暂停时停止无用工作继续有效。性能目标没有取消，也不延后到发布前才测量。

## 3. 新的场景实现路线

推荐 Three.js 承载的 **分层 2.5D 插画场景**：按深度排列的云层、山体、树影，加轻量几何铁路和列车。2.5D 是美术与投影方法，不是新增 SDK 渲染类型。

### 3.1 云层与资产

- 从 A 拆出大云墙、中景云团、低平云海、远山和天空六类形状关系；先把一个真实渲染画面做对。
- 首选少量可重组云形轮廓/明暗遮罩或简化浮雕网格，程序决定布局、尺度、遮挡、间距和变化。
- 若需要离线绘制的局部素材，可以使用原创且来源有记录的素材。不得把“必须纯程序”当成质量障碍，也不依赖在线实时图像生成。
- 云形素材尽量保存中性形状、体积/受光信息；不把夕阳橙色与高光烘死，避免夜景只是给整幅图套蓝色。
- 不把 A 整张图切成几层平移当成最终无限生成；不将参考视频画面装入运行时。
- 控制透明层覆盖和纹理体积；贴片不自动等于低功耗。大云块遮挡、批处理、离屏回收和有界缓存必须随样板建立。
- 第一张运行时画面不过视觉关，不扩写世界生成；若首选云形方法达不到层次，则替换该模块，而非继续堆功能。

### 3.2 场景模块边界（计划，不代表已有文件）

| 模块 | 职责 |
| --- | --- |
| scene.ts | 组装、更新、渲染、释放；不继续集中全部美术代码 |
| composition.ts | 横屏主体尺度、天空开口、前中远景层次、21:9 扩展 |
| cloud-field.ts / 云材质 | 云形组合、遮挡、体积色阶、实例与缓存预算 |
| landscape.ts | 山岛、松树剪影、空气透视 |
| railway.ts / steam-train.ts | 连续桥梁、机车轮廓、车窗、低速轮组、蒸汽池 |
| world.ts | seed + 区段索引、构图规则、区段衔接与回收 |

先按实际复杂度拆分，不创建空模块或抽象框架。旧 cloud-geometry.ts、atmosphere.ts、天空 shader 在新实现替代后删除其失效路径和专属测试；旧截图、版本与文档作为历史保留，不维护两套正式云海实现。

## 4. 昼夜与运动契约

- 默认完整周期 1800 秒**有效播放时间**，默认从接近 A 的暖霞时段开始。它不是现实地理日照，也不与系统时间绑定。
- 黎明 → 白天 → 暖霞 → 蓝调 → 月夜 → 黎明；色板与受光方向均连续，周期首尾连续。
- 各时段比例作为美术参数调校，不能让中午长期泛白、夜间长期全黑；A 和 C 都需要保留足够停留时间。
- 所有对象读同一 LightingState：天空顶/地平线色、主光方向与色、环境光、云亮部/中间调/阴影、远景空气色、日月可见度、车窗亮度。
- 云、山、桥、车与蒸汽均响应光照。昼夜转换期间世界不重建、不换 seed、不跳镜头。
- 车窗从日间弱暖色逐渐转为夜间可读暖点；不使用 bloom 或实时阴影贴图作为默认依赖。
- 将旅行距离、昼夜相位、蒸汽年龄分开：速度为 0 只停车，昼夜与云的细微活动继续；暂停画面则所有视觉时间冻结。
- Focus 只温和降低行进/小事件，不改变昼夜周期长度；Relax 不重置或强制跳到日出。
- 隐藏/最小化/睡眠期间冻结视觉时间，恢复不追补隐藏时长。公开支持的时钟应保留真实活动时长；现有每帧 delta 截断逻辑需检查，避免低帧率时半小时循环变成更长。物体模拟的大步长限制与昼夜累计分离。
- 固定时段模式可选择时间；回到自动模式从当前时间继续。调整周期保留当前相位，不跳天色；画质切换、resize 和上下文恢复保留相位。
- 第一版用户控件：自动昼夜/固定时段，自动周期默认 30 分钟，可提供 15/30/60 分钟；调试另有快速时间扫描，不把快进当作实际观感证据。

### 蒸汽

烟囱间歇吐出少量柔和浅灰蒸汽，向列车后方缓缓飘散，随光照改变色温。初始尝试 8–16 个可见烟团的固定池，数量和发射节奏经动态观察再定；发射间有停顿，生命周期结束回收。它是机车叙事细节，不是装饰性粒子表演。不做厚重黑烟、不铺满天空、不频闪，不要求流体模拟。暂不添加汽笛或轮轨声音。

R1 就设计昼夜用的材质通道，并用三个固定时段检查；R3 再完成时钟和完整过渡。R1/R2 同时测基础开销，不能等 R5 才发现路线过重。局部模块可先推进，但视觉关口未通过时不扩展其他场景或竖屏。

### R1 具体起手任务

1. 用 A 作主参考，明确古典机车 + 煤水车 + 3–4 节客车的比例；沿用 A 的整体密度，不重新偏向 B。
2. 确定天空开口、大云墙、云隙、山岛与桥梁的前后关系，先在 16:9 实际画布里完成一帧。
3. 在一套云形上验证暖霞与月夜受光；不能只展示新的 AI 效果图作为实现完成。
4. 记录内部像素、draw calls、纹理估算体积、帧提交耗时；观察透明叠加的代价。
5. 展示真实运行图与 A 并列检查，决定继续或更换云形方案。

### 参数重整

保留行进速度、云量、云形、雾感、取景、光照语义；旧数值映射和旧色调预设不强行继承。云量改变覆盖与云隙，云形改变低云海/高云墙关系，雾感改变远近分离，取景改变主体与世界尺度；任何极值仍保持可辨列车和完整桥轨。参数改动平滑生效，不能靠瞬间重新随机场景制造“大变化”。一处 daylight 滑杆不再同时承担时刻与亮度。

## 6. 验证与预算

- 现有省电 0.6M 像素/20 FPS、平衡 1M/30 FPS、高质量 2.1M/30 FPS、DPR 上限 1.5 保留为初始对照配置，不作为美术探索的硬上限。需要时显式启用并记录实验预算，最终档位依据视觉与设备测量重新确定；不以提高默认帧率代替美术改进。
- 沿用预热后应用关联进程总内存 200–300 MB 初始目标，持续超过 400 MB 必须分析；数值是目标，不是承诺或通过结果。
- 纹理按实际尺寸、通道与 mip 估算 GPU 存储，同时记录载入解码峰值。几何少或 CPU 低不等于 GPU 省电。
- 固定 seed、视口、时段进行效果对照；默认参数 + 主要参数极值均需查看，不能只展示挑选的一帧。
- 新矩阵：16:9 与 21:9 × 至少 3 个 seed × 暖霞/日间/月夜；另测连续缩放和窄窗安全性，不做竖屏美术矩阵。
- 录制/观察至少 5 分钟自然速度动态、完整 30 分钟昼夜；加速扫描补查时段与边界，但不替代真实周期。
- 发布前/设备稳定性验收执行 2 小时连续播放和 50 次重载/换 seed（本轮不以纵版切换为要求）；日常开发交付使用一分钟循环与短回归，长测单独安排，不逐次阻塞交付。
- 测试昼夜首尾、改变周期、停车/暂停区别、上下文恢复；世界区段边界和创建失败清理。保留仍有效的引擎与平台回归，移除被替换算法的无效断言。
- 功耗对照在同亮度、分辨率、电源、办公任务条件下，分别记录未运行/播放/办公/办公加播放，每种预热后至少 20 分钟。CPU、GPU、关联进程内存和可获取的温度/风扇均记录。
- Windows 安装包成功不等于实际系统事件完成。Mac 2019/2014、普通 Windows 集显、Apple Silicon 分别列状态；未测保持未测。
