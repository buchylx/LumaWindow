版本：0.2 · 日期：2026-09-17 · 状态：总体产品目标；已有技术原型，视觉未验收

先完成 A 概念稿风格的横屏云海，古典蒸汽列车偶尔冒出柔和蒸汽；同一世界约 30 分钟完成昼夜循环，夜景参考 C。当前不做竖屏专属与横版竖屏回退美术，先完成 16:9，再验证 21:9。以下横竖屏、五场景、完整 Focus 等仍是总体产品目标，不是本轮交付要求。执行与验收以 [更新后的第一阶段计划](./PHASE_1_DEVELOPMENT.md) 为准。

## 1. 产品定位

> A calm second screen for people who work all day.
>
> 为长时间工作的人，打开一扇安静的窗。

LumaWindow 是面向双屏工作者的 Ambient Desktop 应用。用户在主屏工作，在副屏播放持续演变的风格化景色，搭配可选环境音、舒缓音乐与专注／休息节奏。场景核心同时运行于网页、Windows 和 macOS 桌面端，项目开源，允许创作者贡献场景。

产品承诺是安静的陪伴、好看的副屏和温和的休息提示；不承诺医疗效果或促进特定神经递质分泌。

### 1.1 目标用户与场景

- 长时间使用双屏的开发者、设计师、写作者及其他桌面工作者。
- 副屏间歇空闲，希望一键进入低干扰的环境播放。
- 使用竖屏或超宽屏，期望画面有针对性的构图。
- 希望使用番茄钟，但不想被强烈提示音或主屏弹窗打断。
- 希望开发、分享程序化艺术场景的创作者。

### 1.2 核心成功条件

1. 首次启动能快速看到漂亮的动态画面，无需先配置一组技术参数。
2. 用户偶尔看一眼能发现景色变化，工作时又能自然忽略它。
3. 横屏、竖屏都拥有完整构图；云海列车拥有两种专属观看方式。
4. 连续运行不会出现明显卡顿、内存持续增长或令人困扰的风扇噪声。
5. 用户无需注册、云服务或在线生成额度即可使用桌面内置场景。
6. 创作者能从最小模板开始，在不修改宿主的情况下添加一个场景。

### 1.3 首版范围

| 必须交付 | 首版不包含 |
| --- | --- |
| Windows、macOS 应用、网页 Live Demo | 原生屏保、桌面壁纸嵌入 |

## 2. 体验原则

**最高视觉准则：安宁、和谐、诗意、放松。低资源占用是核心体验要求，与美术质量共同决定方案，不是发布前再补的优化。**

开发策略已确认：先让 A 风格的实际动态画面达到视觉目标，性能从样板开始同步测量，再依据证据确定预算与画质档位。初始预算允许在有记录的视觉实验中暂时超出，不以未经实测的省电上限压低美术目标。最终交付仍需验证长期资源占用与主屏工作影响。画质降档优先调整内部清晰度、远景细节与帧率，尽量保留构图、主要云形、色彩和昼夜体验。2014 年 Mac 用于探索兼容边界，不决定整个产品的视觉上限。

- 美感主要来自构图、配色、形状、留白、远近关系和缓慢运动，不以特效数量或渲染复杂度体现质量。
- 避免炫丽粒子、装饰性光晕、镜头耀斑、强泛光、光轨与密集闪烁；官方场景与社区收录均遵守此原则。
- 雨滴、雪、少量萤火等有场景意义的自然元素可以使用，但必须克制、低对比、数量有界，不成为吸引注意力的表演。
- 柔和受光、暖色车窗与云层明暗可以保留，优先通过配色与简单着色表达，不依赖昂贵光效。
- Relax 延续同一份安宁，通过文案、声音层次和轻微色温变化表达休息，不升级成视觉特效演出。
- 在可接受的视觉效果下选择资源成本更低的实现，为主屏工作留出 CPU、GPU 与内存余量；不以跑满高帧率为目标。

### 2.1 安静但不静止

- 秒级：云雾、雨滴、水面等细微运动。
- 分钟级：新云层、街区、星域逐渐进入画面。
- 数十分钟级：天气、色温、日照缓慢演变。
- 不使用突然闪白、强烈镜头摇晃、频繁大物体迎面出现或高对比闪烁。
- Focus 状态降低运动和显眼事件；Relax 增加光线或细节变化，不默认大幅加速。

### 2.2 无限变化的定义

通过程序化生成、有限原创素材和受约束的随机规则产生长期连续变化。世界分段生成并回收，内存有界；允许基础素材重用，不承诺数学意义上的永不重复。避免明显整段视频循环和跳切。

同一个种子和场景版本可以重现同一套世界规则，但不要求不同 GPU 的像素完全相同。用户“换一个景色”改变种子；普通调整窗口不更换世界。

### 2.3 默认即可欣赏

每个场景基础面板提供 4–6 个语义清楚的参数。渲染分辨率、帧率等放入应用画质设置，噪声倍频等算法参数只允许出现在创作者调试工具中。默认预设经过横竖屏共同验收。

## 3. 场景、构图版本与屏幕适配

### 3.1 术语

- Scene（场景）：一个主题家族，例如“云海列车”。
- Variant（构图版本）：该主题下独立设计的观看方式，例如“横向远眺”“纵向穿行”。
- Preset（预设）：参数组合，例如“金色黄昏”。
- Seed（种子）：控制程序化世界变化的值。
- Responsive Layout（响应式构图）：同一个版本根据实际宽高比调整取景、主体位置和元素分布。

### 3.2 决策

**同一个场景可以有多个专属构图版本；每个场景必须提供一个能适配横竖屏的基础版本。**

专属版本可以分别实现镜头和运动逻辑，尽可能共享素材、天气、配色、声音与生成算法。无需强迫所有差异进入一个动画程序，也不复制整套应用。

社区首版收录规则同样要求基础版本在最低验收比例下可用。专属版本声明推荐比例；手动选用非推荐比例时仍不能拉伸或丢失关键主体。

### 3.3 用户选择

场景库只显示一张场景卡。场景设置内显示：

> 构图：自动 / 横向远眺 / 纵向穿行

- 默认“自动”，根据播放窗口比例选择对应专属版本；无对应版本时回退基础版本。
- 手动选择优先于自动判断，不因窗口旋转而被覆盖。
- 窗口微调只调整当前构图，不重启场景、不改变种子。
- 自动切换需等待尺寸稳定，并在接近正方形时保持当前版本，避免来回切换。
- 跨版本切换采用淡出、载入、淡入；保留共享参数、声音开关、种子和 Focus 进度。
- 横版与竖版不保证世界位置逐点对应，允许保留主题与时间后重新布置几何。
- 21:9 使用横向版本扩大世界可见范围；不能简单横向拉伸。

### 3.4 验收比例

官方场景至少验收 16:9、21:9、9:16，以及窗口连续缩放、跨不同缩放比例的显示器移动。1:1 和 4:3 要保证可用，最终美术优先级低于前三种比例。极窄窗口可显示最小尺寸提示，不强行保证完整体验。

## 4. 官方首版场景

### 4.1 云海列车 · Cloudsea Railway

旗舰视觉：以已确认的 A 暖霞云谷为整体目标，层叠云海、山岛、细小古典蒸汽列车与拱桥形成辽阔的慢旅程；C 月下远山为夜景参考。云层需有丰富冷暖和体积层次，不以灰蒙单色表达安宁。具体见 [视觉规范](./VISUAL_DIRECTION.md)。画面、代码、素材需原创或具备合适许可。

古典机车、煤水车和少量客车保持可辨轮廓，烟囱间歇吐出少量柔和蒸汽，数量有界、不做炫技粒子。默认约 30 分钟有效播放时间完成昼夜循环，可切为固定时段；旅行速度与昼夜速度独立，停车不会停止天色变化，暂停画面则冻结所有视觉时间。暖霞、白天、蓝调、月夜连续变化，同一世界不换背景或重置。用户无需立即准备美术或音乐资源，允许采用可重组的局部原创素材结合程序生成。

**横向远眺（基础版本）**

- 固定侧面远景，长桥横贯云海，列车缓慢经过。
- 云层具有前后遮挡、边缘细节和有限层次的明暗色块。
- 竖屏兼容时桥梁下移、调整主体尺度并增加上下云层，而非截取横图中央。
- 列车离开取景后的空镜时间应受控；窄屏下需保证有足够的可见时间。

**纵向穿行（竖屏专属版本）**

- 高位斜俯视，列车位于画面下方约三分之一处，朝屏幕上方前进。
- 铁轨从下方向远处云雾延伸，环境缓慢向下移动。
- 轨道偶尔平缓转弯，桥塔、云隙和光线有节制地出现。
- 使用纵向飞行游戏的空间组织方式，但保持舒缓速度，不引入战斗、障碍躲避或追逐感。

共享参数方向：行进速度、云量、云形、雾感、取景、自动昼夜/固定时段及周期。默认周期 30 分钟。环境音为后续的轻柔风声和远处列车声，本轮不新增正式音轨。当前首选 Three.js 承载的分层 2.5D 实现，用局部云形、统一受光、轻量列车/桥梁和程序化布局共同呈现，不锁定纯 Shader 或纯程序造型。竖屏参数共享在横屏通过后再设计。

### 4.2 雨夜归途 · Rainlit Walk

小小的撑伞者在温暖灯光映照的长街漫步。基础版本使用适合多比例的斜后方镜头，横屏可偏侧向展开，竖屏强调向远处延伸的街道；首版不强制做第二个专属版本。

- 街区按色板、建筑比例、灯光密度规则分段生成。
- 人物步行连续，雨、积水、灯光倒影构成主要观赏细节。
- 基础参数：雨量、步速、灯光冷暖、雾量、倒影强度。
- 环境音：雨、轻微脚步；音乐可独立关闭。
- 推荐 Three.js Scene。

### 4.3 星海漂航 · Starbound Drift

小飞行器在广阔星云中缓慢漂航，远方行星逐渐显现。首版是风格化星域，不模拟完整天体系统。

- 星域分块生成；行星稀疏出现，避免突现与穿模。
- 横屏主体偏侧，竖屏主体偏下，前方空间保持留白。
- 基础参数：航速、星密度、星云色调、行星频率、背景明度；不提供炫丽光晕或高速光轨预设。
- 环境音使用艺术化低声纹理，可关闭；不宣称真实太空声音。
- 推荐 Three.js Scene。

### 4.4 浮光水庭 · Sunlit Pond

俯视水面，睡莲、叶片、柔和光斑和偶尔经过的鱼影。提供明亮清新的日间体验，也是 Canvas 创作者示范场景。

- 根据画布形状重新布置留白与睡莲，鱼群路径适应边界。
- 涟漪、漂移和游动受约束，避免对象无限堆积。
- 基础参数：水色、涟漪、鱼数量、落叶、光照。
- 环境音：轻水声、可选少量自然声。
- 推荐 Canvas 2D Scene。

### 4.5 雾林小屋 · Mistwood Cabin

深林中一盏暖灯，薄雾穿过树木。固定构图提供较少空间移动的安静选择。

- 横屏展开树林，竖屏展示树冠高度，小屋始终保持可辨识。
- 雾层、细雨、晨昏和少量萤火持续变化。
- 基础参数：雾量、雨量、灯光、季节色调、萤火密度。
- 环境音：森林、风、可选雨声。
- 推荐 Shader Scene。

## 5. 信息架构与主要流程

### 5.1 桌面端界面

1. 控制窗口：场景库、当前场景静态预览、播放位置、参数、声音、Focus、应用设置。
2. 播放窗口：场景全画面、自动隐藏的轻量控制、休息提示。
3. 托盘菜单：打开控制窗口、暂停／继续画面、静音、退出。

控制窗口不再运行完整动态场景，避免双份 GPU 消耗。首版只有一个播放窗口。

### 5.2 首次使用

1. 打开应用，控制窗口展示默认云海列车预览。
2. 有多个显示器时建议非主屏，用户确认播放位置；单屏则打开普通窗口。
3. 点击“开始播放”，显示默认场景，隐藏控制不影响主屏工作。
4. 声音初始关闭，用户主动开启后淡入；记住音量偏好。
5. 可选择 Ambient 或启动 Focus，不强制进入计时模式。

后续启动恢复场景与偏好，不自动开始新的 Focus 会话；默认仍由用户开始播放并启用声音，避免意外外放。

### 5.3 播放操作

- 指针移动或键盘聚焦显示控制；无操作约 3 秒后淡出，键盘焦点所在控制不消失。
- Esc 退出全屏，F 切换全屏，M 静音；输入控件内不触发快捷键。
- 播放窗口“暂停画面”和“暂停专注”使用不同动作，避免误解。
- 画面暂停不停止 Focus；声音单独控制。
- “换一个景色”更新种子并柔和过渡，不重置 Focus。
- 全屏是普通应用全屏，不默认置顶、不隐藏其他应用、不嵌入桌面壁纸层。
- 关闭控制窗口可保留播放及托盘；明确“退出应用”关闭全部窗口和声音。
- 关闭播放窗口结束播放并暂停当前 Focus，控制窗口仍可重新开始。

### 5.4 网页 Demo

- 同页场景与可收起控制面板，默认云海列车静音播放。
- 用户点击开启声音或进入全屏；不依赖自动播放音频。
- 不能承诺自动把网页移动到副屏：提示用户拖动浏览器窗口后全屏。
- 首版 Demo 不承诺离线缓存；桌面包必须包含所需资源并离线工作。
- 页面后台运行受浏览器限制，返回页面时校准 Focus 状态，不能承诺后台精确出声提醒。

## 6. Focus 与 Relax

### 6.1 默认设置

| 项目 | 默认／规则 |
| --- | --- |
| 模式 | Ambient，计时需主动启动 |
| Focus | 25 分钟，可配置 1–180 分钟整数 |
| Relax | 5 分钟，可配置 1–60 分钟整数 |
| 下一轮 | 默认自动继续，可改为手动 |
| 倒计时 | 默认隐藏，控制面板中可见 |
| 提示音 | 默认关闭 |
| 长休息 | 首版不包含 |
| 改时长 | 应用于下一个阶段，不改当前阶段截止时间 |

### 6.2 状态与转换

Ambient → 主动启动 → Focus → 时间到 → Relax → 自动 Focus 或等待用户继续。

Focus、Relax 均可暂停／继续、跳过当前阶段或结束会话返回 Ambient。手动继续开启时，休息结束停留在“准备好再开始”，使用平静场景，不反复提示。

休息开始时用约 10–20 秒过渡到休息氛围，文字淡入：

> Take a break.
>
> 看看远处，放松一下肩膀。

辅助文案按界面语言显示；不要求强制执行呼吸训练。提示显示约 15 秒后收为小字状态，可在设置中关闭。恢复专注时文字淡出，不抢键盘焦点，不弹主屏窗口。

### 6.3 特殊情况

- 最小化播放窗口：画面暂停，Focus 继续，已开启的音频继续；不会强制弹出窗口。
- 系统锁屏／睡眠：桌面版暂停音画与 Focus；解锁／唤醒后显示待继续状态，不突然播放声音。
- 异常退出再启动：恢复为暂停会话，显示剩余时间，不自动补跑多轮。
- 网页切到后台：逻辑时间继续；恢复时若当前阶段已过期，最多进入下一个阶段，并从恢复时开始该阶段，不追补多个周期。
- 系统时间大幅调整：按计时模块的异常处理进入待继续状态，不瞬间完成多个周期。

## 7. 声音设计

独立音量：主音量、环境音、音乐；提醒音独立开关。环境音与音乐都可以单独静音。

- Focus 使用更稀疏、平稳的声部；Relax 可以加入轻旋律或更明亮的音色。
- 优先使用兼容的分层音轨交叉淡化，避免阶段切换时硬切歌曲。
- 用户音量设置是基准，阶段变化不得突然突破该上限；混音留有余量，避免削波。
- 不要求音乐无限原创；合法音轨可以无缝循环或按规则组合。
- 短环境音可解码循环，长音乐避免全部解码造成高内存占用。
- 加载失败时画面继续，提示声音不可用并可重试。

## 8. 显示器、性能与可访问性

- 默认使用满足画面品质的最低合理渲染成本；高质量档只改善清晰度与稳定性，不增加装饰性特效，也不作为默认档。
- 首先使用低成本分层、简化几何和着色方案；昂贵体积效果、多通道后处理、实时阴影须以实际观感收益和基准测试证明必要性。
- 性能验收同时检查对主屏常见工作操作的影响；只有场景自身流畅而明显拖慢工作，不算通过。

- 记住显示器偏好；设备不可用时回到可见屏幕的普通窗口，不在主屏强制全屏。
- 显示器名称、位置与缩放都可能变化，恢复偏好以“尽量匹配”为原则。
- 默认目标 30 FPS，提供省电／平衡／高质量三档与高级渲染比例设置。
- 4K 屏幕不要求原生 4K 渲染；UI 保持清晰，场景按画质预算渲染。
- 无法使用 WebGL 时提供明确提示和可运行的 Canvas 场景入口，不静默黑屏。
- 提供“减少动态效果”，降低移动、减少显眼事件、取消大幅镜头变化。
- 控制界面支持键盘、可见焦点、文字对比度与中英文；休息文案应有独立背景遮罩保证可读性。
- 基准硬件尚未测定；性能数字是开发目标，公开承诺必须依据实际设备测试。
- 已知开发机为 i7-12700KF、RTX 3080、32 GB RAM、Windows x64；屏幕参数待补充。该机器作为开发与高配回归环境，不作为最低配置或低功耗验收依据。不记录设备 ID、产品 ID 等无关标识。
- 首版以普通集显、8 GB 内存的 Windows 笔记本和 M1、8 GB 内存的 Mac 作为候选验证档位；具体型号和最低系统版本在实测后确定，不提前承诺所有旧机流畅。
- 性能要求是持续播放时不明显扰动主屏工作，避免持续高负载、显著风扇升速及内存增长。分别测试纯播放和办公并行，不能只以 FPS 合格判定成功。
- macOS 从 M0 同步设计与验证。朋友可提供的 2019 年 16 英寸 MacBook Pro 作为首批 Intel Mac 重点测试机，2014 年 MacBook Pro 用于探索旧设备兼容与性能边界；两台机器的准确配置和已安装 macOS 版本待确认。Apple Silicon 仍保留正式支持目标，M1／8 GB 候选测试机尚未落实；未通过相应实机验收的架构必须标明未验证。
- 2014 年设备先验证能否安装启动、WebGL 能力与场景正确性，再测试省电档及功耗。不为通过测试要求用户升级系统或采用非官方系统补丁；是否纳入正式支持范围依据实际系统、工具链和场景表现决定。
- macOS 验收包含 Retina 分辨率预算、外接竖屏、Spaces／全屏、菜单栏入口、锁屏／唤醒和窗口关闭行为。网页 Safari 正常不代表桌面 WKWebView 已完成验收。

### 10.1 首版验收清单

- [ ] 五场景体现安宁、和谐、诗意和放松，无炫技粒子、装饰性光晕或密集闪烁；Relax 不增强为特效演出。
- [ ] 默认档资源开销有实测记录，主屏工作没有明显受扰；高质量档不额外添加装饰性效果。

- [ ] 五个场景均持续生成变化，参数调整平滑且可恢复默认。
- [ ] 云海两个专属版本可手选，自动选择及基础版本回退符合预期。
- [ ] 三种重点比例无拉伸、主体丢失或控制遮挡；窗口缩放不重置世界。
- [ ] Focus、暂停、跳过、手动继续、休息文案及音频过渡符合上述规则。
- [ ] 双屏选择、跨 DPI 移动、拔屏、最小化、锁屏／唤醒可恢复。
- [ ] 2 小时连续运行稳定，切换场景 50 次无持续资源增长；具体指标见架构文档。
- [ ] Windows 与 macOS 干净安装和无网络启动可用，网页声音受限时能主动恢复。
- [ ] 快捷键、中文／英文、减少动态效果可用。
- [ ] 场景代码和所有随包素材有完整许可记录。
- [ ] 新贡献场景可从模板接入，不修改宿主业务代码。

### 10.2 首版仍需验证或决定的事项

这些事项不阻塞接口设计，但必须在相应里程碑关闭：

1. M0：A 风格横屏的实际美术表现、昼夜与持续生成，以及依据实测确定的设备档位和性能预算；竖屏在横屏验收后再设计。
2. M1：Windows／macOS 最低支持版本、两平台锁屏／睡眠通知的可靠实现。
3. M2：五场景配乐来源与许可、每个场景的正式参数范围。
4. M3：最终开源许可、GitHub 仓库归属、Demo 域名／托管、签名与分发方式。

文中首版行为是建议的实施默认值；任何后续变更应同步更新本文件和架构文档，避免两份规范冲突。
