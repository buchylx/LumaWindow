# 第一阶段开发计划：云海列车双构图与平台验证

版本：0.2 · 日期：2026-09-15 · 状态：执行依据；已有原型，阶段验收未完成

本文定义第一阶段的具体任务和完成条件；当前实现、测试证据与缺口统一记录在 [阶段执行与实测记录](./validation/PHASE_1_RESULTS.md)。任务说明不代表相应功能已经验收通过。

## 1. 阶段定义

本文件对应总体架构中的 **M0：视觉与高风险技术验证**。对外称“第一阶段”，不把它与总体计划中的 M1 混用。

阶段目标：交付一个可运行的云海列车动态样板，包含横向远眺、纵向穿行、基本参数和画质控制；同一套场景在网页、Windows 和 macOS 外壳中进行验证，形成可追溯的视觉与性能结论。

阶段完成后进入 M1，再实现完整 Focus 状态机、正式声音系统、偏好保存和控制／播放窗口业务。第一阶段不等于完整首版。

依据：

- [产品设计](./PRODUCT_DESIGN.md)：产品行为、范围与体验原则。
- [总体架构](./ARCHITECTURE.md)：模块职责、接口方向、性能预算。
- [视觉方向](./VISUAL_DIRECTION.md)：参考分析与待验证的原创提案。

发生冲突时，已确认的用户要求优先；本文件只细化 M0，不静默改变总体范围。视觉提案“晨雾中的空中轻轨”为工作起点，可在样板反馈后调整。

## 2. 不可退让的要求

1. 安宁、和谐、诗意、放松；低资源占用与画面品质同时验收。
2. 不使用炫丽粒子、装饰性光晕、强泛光、镜头耀斑、光轨和密集闪烁。
3. 不把视频截图用作场景背景或纹理，不复刻原作具体桥型、云形、配色组合和排版。
4. 横向和纵向版本分别构图；纵版有向屏幕上方行进的空间感，不旋转横版画布凑数。
5. 基础横向版本在竖屏也可用；所有版本处理实际宽高比，禁止拉伸。
6. 场景持续生成、回收资源，不用一段循环视频替代，也不无限积累对象。
7. 不因开发机拥有 RTX 3080 就采用高开销默认实现。
8. 实测、未测和推断明确区分；构建成功不代表 macOS 画面、音频或低功耗验收通过。

### P01：盘点环境与建立基线

- 检查现有文件和项目指令，保留参考视频及文档。
- 确认 Node、pnpm、Rust、Windows 构建工具版本；安装或配置缺失项时遵守当前环境权限。
- 检查 Git 状态；没有仓库时可初始化本地仓库，不创建远程仓库、不推送。
- 建立 .gitignore，精确排除原始参考视频、参考截帧、依赖、编译产物和本地性能日志，不批量忽略所有未来图片／视频素材。
- 记录开发机 GPU、驱动、显示器分辨率、系统缩放和电源模式；不收集设备 ID、序列号。
- 建立 `docs/validation/PHASE_1_RESULTS.md`，所有结果初始为“未测”。

验收：工具链有版本记录；未覆盖现有文件；开发机与低配基线角色明确。

### P02：原创构图稿与视觉约束

- 制作横向、纵向各一张概念稿。使用图像工具时按对应技能工作；本任务不指定必须采用 AI 图像。
- 横版：轻微斜向高架、短列车、云隙、少量远山轮廓；避免连续悬索桥横贯画面的参考组合。
- 竖版：列车位于下方约三分之一，轨道朝上方延伸，远处消失于雾。
- 试用灰青天空、米白亮云、淡紫云影和少量杏金暖窗；局部明暗清楚但不过曝。
- 标注哪些部分程序生成、哪些使用简单几何；第一阶段无需采购美术素材。
- 将草稿呈现给用户并允许反馈；反馈未到时可推进工程与可逆动态草样，不据此宣称美术已定稿。

验收：两张图有独立完整构图；视觉说明与截图复刻明显区分；没有依赖炫技特效。没有审美确认时在报告中保留“待视觉反馈”。

### P03：最小工程骨架

本阶段实际创建：

```text
apps/player/src/              # 网页与桌面装配，调试播放器
apps/player/src-tauri/        # Tauri 配置与平台探针
packages/scene-sdk/src/       # 类型、参数和能力声明
packages/scene-engine/src/    # 循环、加载、切换、时间和质量
packages/renderer-shader/src/ # 简单全屏 Shader 入口
packages/platform/src/       # Web/Tauri 能力适配
scenes/cloudsea-railway/      # shared、variants、manifest
docs/concepts/               # 自有构图稿与说明
docs/validation/             # 实测记录与复现步骤
```

不提前创建空的音频包、四个场景或状态管理框架。React 每帧不 setState；诊断 UI 约每秒刷新一次。

验收：依赖版本锁定，TS strict，网页可启动和生产构建，平台特有 import 不进入共享场景包。

### P04：最小引擎与生命周期

- 实现总体架构中的 SceneManifest、VariantManifest、Viewport、FrameContext 与 SceneInstance 必要字段。
- 注册一个云海主题、两个版本 ID；版本模块懒加载，参数做运行时校验。
- 宿主只有一个活动帧循环，渲染实例只实现 update/render，不自行启动第二个 requestAnimationFrame。
- 限帧时累计真实活动 delta；不要把每帧固定值累加成假时间。
- 场景活动时间在暂停／不可见时冻结；恢复重置上一帧时间，限制大 delta，避免跳跃。
- resize 更新像素预算、视口与构图，不改变 seed 和活动时间。
- 实现递增请求号、AbortSignal 和迟到实例释放，切换使用低亮遮罩，不同时渲染两个重场景。
- 加载错误提供重试及诊断，WebGL 不可用时给清晰提示；本阶段尚无正式 Canvas 场景，不冒充完成最终回退功能。

验收：暂停、恢复、resize、连续切换、创建失败、dispose 可单独复现；旧循环、监听器和资源不残留。

### P05：横向远眺

实现起点：低成本分层云场 + 简化轨道和列车；优先在 Shader 入口内验证，不使用高步数体积云。

- 云层具有大形、体积色块和稀疏边缘细节，远层更低对比。
- 列车和桥梁可先使用分析形状／简单几何，保证轮廓稳定与比例正确。
- 云层慢速运动，轨道和世界分块复用；局部时间和坐标重置避免长时浮点问题。
- 轨道连接连续；参考种子至少三组，不存在常驻空白区或主体长期完全遮挡。
- 16:9 为主构图；21:9 扩展可见世界；9:16 下调整轨道高度、主体比例和云层布局。

验收：连续观看 5 分钟无明显接缝、噪声闪烁、机械整段循环或突变；9:16 基础回退仍可欣赏。

### P06：纵向穿行

- 与横版共享随机工具、色板和主体造型原则，但独立实现镜头／投影、轨道和云分布。
- 列车向上行进，环境向下缓慢移动；允许列车屏幕位置基本固定。
- 轨道以有限曲率延伸，分块交界位置和切线连续，不出现突然折角。
- 相机保持稳定；禁止高速迎面穿越、闪烁星点或游戏式速度线。
- 9:16 为主构图，也验证用户手动在横屏选用时可用。
- 若 Shader 假透视难以稳定表达轨道，可实现最小 Three.js 几何版本；在决策记录中解释视觉／成本依据，不因此展开完整 Three.js SDK。

验收：观看方向明确，轨道不会断裂或穿越列车；横竖两个版本具有一致的世界风格。

### P07：调试播放器

提供以下控件，不做正式产品场景库：

| 控件 | 阶段默认行为 |
| --- | --- |
| 构图 | 自动／横向远眺／纵向穿行 |
| 云量 | 0–1，默认 0.55 |
| 雾感 | 0–1，默认 0.35 |
| 行进速度 | 0–1，默认 0.2；0 为停止行进，不等于暂停全部动画 |
| 光照时段 | 0–1，默认 0.35；数值映射风格化光照，不绑定真实时间 |
| 色调 | 晨雾／暖晨／蓝调三套受控预设，不开放任意高饱和拼色 |
| 画质 | 平衡默认；省电／高质量手动选择 |
| 动画 | 暂停／继续，换种子，恢复参数默认 |
| 氛围预览 | 手动 Ambient／Focus／Relax，15 秒平滑过渡，无计时器 |
| 诊断 | 默认隐藏，显示实际内部尺寸、帧间隔、CPU 提交耗时、对象统计 |

参数范围和默认值为草样初值，调校后更新 manifest 与文档。UI 标签使用自然语言，0–1 只作为内部值。

自动构图采用总体设计：≤0.85 偏竖、≥1.15 偏横，中间保持当前版本，初次使用基础版本，尺寸稳定 600 ms 后切换。手动选择始终优先。

验收：快速拖动参数不卡 UI，最终值可确定；切换保留共享参数、seed、活动时间和氛围 blend；全屏受平台限制时说明原因，不假报成功。

### P08：Windows/macOS 平台探针

采用最小测试控制页与播放页验证将来的双窗口架构，不在 M0 实现完整 AppCore。

- 枚举显示器、创建／定位播放窗口、进入／退出全屏，按 Esc 能返回。
- 主屏点击控制时副屏画面继续，不把失焦当作不可见。
- 关闭测试控制页不产生第二份场景或声音；退出应用释放全部资源。
- 从控制页发起音频启用请求，检查播放页是否真正解锁；失败提供播放页主动点击入口。
- 测试音主动点击才播放，低音量、短时长，可立即停止，避免高频或持续大声提示。
- 记录锁屏、睡眠、恢复、最小化、拔屏的实际事件；确保画面暂停／恢复不跳跃，不在恢复后突然出声。
- 系统事件若缺少完整支持，标为缺口并记录所需原生桥接，不用浏览器事件伪装验证通过。
- Windows 本机跑通；Mac 使用对应系统构建，提前提供可复现的朋友测试说明。
- 可编写 macOS CI 配置，但没有远程仓库／运行器时标为“未执行”；不为完成文档任务擅自创建远程发布。

验收：分别报告平台结果。macOS 构建、真实 WKWebView 画面、音频与功耗是四个独立检查项。签名／公证属于 M3，朋友测试如受安装流程阻挡则记录，不要求关闭系统安全保护。

### P09：性能、稳定性与观感收敛

- 内部像素预算：省电约 0.6M／20 FPS；平衡约 1.0M／30 FPS；高质量约 2.1M／30 FPS。
- resize 同时考虑设备缩放和总像素预算；4K／Retina 不绕过上限。
- 初始内存目标为预热后总关联进程 200–300 MB，持续超过 400 MB 必须分析；不是未经实测的承诺。
- 每次优化记录改变的算法、观感损失与资源收益，不仅记录截图。
- 优先减少噪声采样、渲染通道、动态对象、纹理和无用重绘；不添加“满屏模糊”掩盖问题。
- 默认档若低配持续发热，即使 FPS 达标也需继续降低成本或调整视觉方案。

验收：遵循第 6 节，保留原始记录与结论；只有 RTX 3080 测试通过时不能标低配达标。

## 6. 验证方法

### 6.1 自动化检查

必测逻辑：

- 参数非法值、NaN、边界和枚举校验。
- 自动构图阈值、稳定等待、中间区间保持和手动优先。
- 像素预算在横／竖、DPR 1/1.5/2、零尺寸时的正确处理。
- 暂停与恢复不推进隐藏时间，resize 不更换 seed。
- 快速 A→B→A 加载、取消与迟到创建，始终只保留一个活动实例。
- dispose 释放调度与资源；创建失败后可以重试。

不为颜色常量、静态文案编写镜像测试。浏览器交互检查覆盖控件、全屏、种子、切换与控制台异常；真实系统行为另做实机检查。

### 6.2 视觉矩阵

两个版本 × 16:9、21:9、9:16 × 至少三组 seed，逐项观察拉伸、主体可读性、轨道接缝、云层闪烁与留白。另测 1:1、4:3 和连续窗口缩放的可用性。

重点观察 Focus／Relax 过渡是否依然安静，默认速度是否适合余光观看；静态漂亮但动态扰人不能通过。

### 6.3 资源测量

在相同亮度、外接屏、电源模式和办公负载下，分别观察：未运行、单独播放、办公、办公加播放。每种状态预热后至少记录 20 分钟；测试过程不保持开发者工具打开作为正式数值。

记录帧间隔、CPU 提交耗时、总应用关联进程内存、GPU 使用情况，以及可获取的功耗／温度／风扇信息。不把 JavaScript heap 等同总内存，也不把 CPU 提交耗时等同 GPU 完成时间。双 GPU 设备记录实际活动 GPU。

第一阶段至少在本机执行 2 小时连续运行和 50 次版本切换；Mac 与低配分别补齐，不从高配推断。记录预热稳态与测试结束后的资源水平，对持续增长查明原因。

### A. 本地实现完成

## 9. 下一步实际开发的起点

全新实施时按照 P01 开始环境盘点，同时准备 P02 横竖原创构图稿，然后搭建 P03 工程。当前仓库已有原型，继续开发时先对照阶段执行与实测记录检查已有交付物，再完成未验收任务，不重复搭建工程。当前不需要用户提前购买模型或音乐，不需要开发者签名账号，也不需要一次决定五个场景的所有细节。

实测需要补充的配置、视觉反馈与发布账号分别在对应阶段处理；外部条件不阻塞可独立完成的工作。本文不授权替用户联系朋友或向外发布测试包。
