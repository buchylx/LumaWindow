# 第二阶段设计：让云海列车更有诗意、更耐看

日期：2026-09-17 · 状态：0.2.0 已实现核心范围，正在运行验收；最终视觉认可与 Mac 实机验收待用户测试。

基线：0.1.3；配套：[视觉规范](VISUAL_DIRECTION.md)、[第一阶段结果](validation/PHASE_1_HANDOFF.md)、[总体产品设计](PRODUCT_DESIGN.md)。

## 1. 为什么现在可以开始

用户已认可近期画面的明显改善，程序生成、横向远眺、蒸汽列车、昼夜循环和分层视差已有可运行基础。Windows 短回归通过，2019 Intel Mac 的网页基础体验正常，因此可以开始下一轮设计和视觉迭代。

这不等于第一阶段全部验收结束：0.1.3 收尾修正的最终观感、Mac 原生运行与生命周期、低配设备和长期功耗仍保留待验收。新设计可以推进，已有平台缺口继续跟踪。

这里的“第二阶段”指第二轮具体开发迭代。总体产品计划中的 M0 / M1 / M2 是另一层里程碑：本轮主要继续完成 M0 的视觉质量与设备证据，为 M1 完整样板做准备；不把进入第二阶段等同于直接启动 M1 全部功能。

## 2. 唯一核心目标

**同一列横向行驶的古典蒸汽列车，穿过持续生成、色彩和空间关系丰富的写意世界；看一眼漂亮，放很久也安静。**

延续 A 暖霞云谷和 C 月下远山，不另换美术方向。保留远眺构图、较长编组、水平铁路和近景掠过；列车具体造型尚未获认可，需要重设计单节比例、机车轮廓、材质主次与蒸汽。自然景物可以超现实；运动和遮挡关系必须连贯。

## 3. 范围与优先级

| 优先级 | 内容 | 希望解决的体验问题 |
| --- | --- | --- |
| 必须 | 古典长途客运列车造型 | 当前偏玩具、煤车的联想，缺少修长与旅途感 |
| 必须 | 昼夜色彩与景深配色 | 白天和月夜平淡，各层只是同色变浅 |
| 必须 | 连绵山景与远山露出 | 山多为孤峰，缺少群峰、山脊与山谷 |
| 必须 | 有组织的沿途变化 | 连续随机有了，但看久后景物结构仍相似 |
| 必须 | 参数的可见作用与连续过渡 | 改参数应改变整体关系，不能只是细微扰动 |
| 配套 | 性能对照与 Mac 原生缺口 | 确认新增画面质量的实际成本，补全平台证据 |
| 可选 | 稀疏飞鸟、桥梁进一步细化 | 增加生活感，仅在主体画面稳定后加入；列车优化不属于可选项 |

完整 Focus 计时、正式 BGM、其他场景、竖屏专属、创作者插件接口扩展与场景市场暂不进入本轮实现。它们仍在总体规划中，避免同时改变画面、使用流程和架构。

### 列车优化纳入首轮样板

参考视频局部与 0.1.3 实际画面对照后，问题集中在单节车厢偏短、机车轮廓符号化、亮边与轮圈主次不足，以及客运身份和拖曳蒸汽表达不够。采用“古典长途客运蒸汽列车”方向，精细重画人工结构，同时保持远眺尺度与安宁气质。详见[列车造型对照与设计](TRAIN_VISUAL_DESIGN.md)。

首轮同时交付列车侧面比例与全景样板，以及白天/暖霞/月夜配色；不再把列车视为已定稿主体，也不把这项工作留到最后添加装饰。

## 4. 昼夜色彩设计

先完成同一世界位置的固定时段画面，再检查连续昼夜。重点先做白天、暖霞、月夜，随后补齐黎明和蓝调连接段。

| 时段 | 主色关系 | 层次要求 |
| --- | --- | --- |
| 黎明 | 冷青蓝天空、低处淡杏与玫瑰光 | 暖色从地平线向云缘扩散，近山仍冷 |
| 白天 | 天青、奶油白、淡杏、蓝紫阴影 | 云顶有亮度，云腹有颜色；远山保持轮廓，避免白块和灰泥感 |
| 暖霞 | 杏金、珊瑚、紫灰、少量冷蓝 | 暖云与冷影成组出现，有明亮开口和安静暗部，不满屏橙红 |
| 蓝调 | 钴蓝、灰紫、地平线残留暖色 | 光逐渐收敛到远处和车窗，不能突然整体变暗 |
| 月夜 | 靛蓝、银紫、冷青、少量琥珀窗光 | 近山、中云、远山分开；深色区域仍可读，不以整体提亮模拟月光 |

将现有按时间输出一组颜色的 `lighting.ts` 扩展为有明确用途的颜色角色：天空顶色/地平线、云亮部/主体/阴影、近中远山、空气色、桥车与窗光。近景和远景在冷暖、明度、对比上分别设计，避免统一混入灰色。

受光色跟随云形与山体结构，不做覆盖全屏的彩色噪声。日月、蒸汽、列车和桥共用同一光照状态。循环首尾连续，停车与昼夜解耦。

禁止用泛光、光束、镜头耀斑、闪烁粒子或提高默认帧率制造“惊艳”。若需要探索新配色，可生成辅助色稿，但验收对象始终是实际运行画面。

## 5. 山景与旅程生成

### 5.1 先决定地形，再画细节

现有山体连续高度场保留为基础，拆开低频山势、中尺度山脊和少量笔触细节。增加可组合的生成规则：连绵山脉、低缓群山、峭峰山岛、开阔云谷。它们是算法和参数范围，不是几张固定完整轮廓的重排。

远景至少能形成连续山脊与其后的天空开口；不能一直被同一层云墙覆盖。中景负责山谷与云隙，前景负责短暂遮挡、掠过与重新露出列车。保留 0.1.3 的统一深度约束。

### 5.2 世界有段落，但画面不切场

加入基于 seed 和世界距离的旅程规划，缓慢改变山势、云墙高度、云海覆盖和天空开口。第一轮仅探索三种组合：

- **层峦云谷**：连续远山与错落中山，云在山谷中穿插。
- **开阔云海**：山体逐渐减少、云墙降低，留出更大的天空与地平线。
- **高云山岛**：少量高山与大云团形成尺度反差，再逐渐回到开阔区域。

不按固定的 A→B→C 顺序循环，不让昼夜时钟控制地形切换。相邻区域在统一世界坐标中混合生成规则，画外进入、画内稳定、离开后回收；禁止整幅背景交叉淡化、山体突然变形或逐帧重新抽随机数。

初始调校目标：默认速度下，每几十秒能察觉局部构图变化，几分钟内能看到明显不同的空间组织。具体区段长度按真实动态调整；速度为零时地形停留，不能为了显示变化继续换地形。

“无限”指沿世界坐标持续生成、没有整段固定背景回放，不承诺数学上永不出现相似形状。复用绘画规则和有界缓存是允许的。

## 6. 参数与天空细节

先增强现有参数，不急于增加滑杆数量：

| 参数 | 应有的明显作用 | 不能破坏的关系 |
| --- | --- | --- |
| 云量 | 开阔山谷与浓密云海的覆盖差异 | 列车不能长期被完整遮住 |
| 云形 | 低平云层与高耸云墙的尺度差异 | 轮廓连续，不能靠换种子跳景 |
| 雾感 | 清晰远山与深远朦胧的空气透视 | 近景对比和主体可读性 |
| 取景 | 主体尺度、天空和近景所占比例 | 桥轨水平，长列车比例稳定 |
| 时段/色调 | 整套冷暖关系与光照氛围 | 色面随形体，不套全屏颜色滤镜 |
| 速度 | 同一旅途的行进快慢 | 深度速度次序、独立天色与风速 |

新增“山势”等参数仅在上述映射仍无法表达关键效果时考虑。极端值可以夸张，但不允许无意义噪声、突然重置或主体永久消失。

高空薄云已有独立风速，继续保留。飞鸟是可选项：远处小剪影、数量有界、间隔稀疏、运动平缓，默认长时间没有飞鸟也成立。暂停/减少动态行为必须与场景一致；不加入频繁流星或其他吸睛事件。

## 7. 开发拆分与每次交付

| 步骤 | 实现边界 | 给用户看的结果 |
| --- | --- | --- |
| S1 列车与色彩样板 | 先定长客车/机车轮廓，再做车体材质与场景配色、蒸汽；固定世界，不同时改山型 | 列车侧面结构及实际全景对照、三时段运行图、自然速度样片与一分钟昼夜样片 |
| S2 山景样板 | 连续山脉、群峰、远山露出；保留 S1 配色 | 同一 seed、同一时段前后对照；正常速度的近景与山脊运动 |
| S3 连续旅程 | 世界段落规划、连续过渡与参数映射 | 默认速度 3–5 分钟实际片段；另看参数极值与至少三组 seed |
| S4 收尾与平台 | 有界资源、画质档位、Mac 原生缺口；必要时加入飞鸟 | 网页/Windows 测试包、Mac 本机构建入口、实测与未测清单 |

每步都以真实场景为样板。本次按用户“完成第二阶段”的指示连续完成 S1–S4，并一起移交真实截图、动态和测试包。交付不代表用户已认可最终美术效果。

## 8. 工程边界

- 保留 TypeScript + Three.js + React + Tauri，共享网页和桌面场景；不为本轮换框架。
- `lighting.ts` 负责时段与颜色角色；`nature.ts` 负责程序山云与色面；`depth.ts` 继续约束视差、遮挡和雾感。需要时抽出纯函数的旅程规划模块，避免把规则全部塞入一个着色器。
- `railway.ts` 中列车允许独立拆分并重画，继续静态几何合批；优先用比例、轮廓与材质主次提升品质，不以高多边形、灯光后处理或扩大主体尺寸代替精绘。
- 固定图层和对象预算，禁止随旅途增长不断追加山云对象。缓存以可视区域及两侧余量为界；若改变预算，必须记录原因及对照数据。
- 着色器增加噪声采样也会增加 GPU 成本；“零纹理”和“draw call 不变”均不能作为低功耗证明。优先共享低频计算、控制细节采样和透明层覆盖。
- 省电/平衡/高质量保留同一构图和配色，先降内部分辨率、细节采样和帧率；不把老机器变成另一套明显失色的美术。
- 第一版色彩/山型可先在现有预算上比较；性能问题需要优化实现或明确实验档，不能偷偷提高默认像素预算。

## 9. 验收方式

### 视觉

- 列车从“短盒与机械符号”转为有可信比例的古典长途客车；正常全景下修长、暖窗克制、蒸汽柔缓，放大检查结构合理。列车造型需单独取得用户反馈。
- 与 0.1.3、A/C 方向并列比较：白天与月夜有可辨的冷暖层次，近中远分离；不以更高饱和度作为唯一改进。
- 至少三组 seed、五个固定时段检查，16:9 和 21:9 均无主体比例、桥轨或遮挡问题。
- 正常速度旅程可见连续山脉、开阔区域和高云组合；没有模板复用感明显的整段背景回放、接缝或突现。
- 参数两端能看出整体构图/氛围差异；无须读参数数值才能辨认效果。
- 用户认可实际动态的诗意与安静程度。截图、概念图和单元测试不能代替这一项。

### 功能与资源

- 停车、暂停、恢复、昼夜环绕、换种子、缩放和场景释放回归；一分钟昼夜用于开发，正常默认仍为 30 分钟。
- 单测验证旅程确定性、区段边界连续性、资源容量及深度约束，不用“正确色号”之类测试证明画面漂亮。
- 同 seed、分辨率、画质、时长比较 0.1.3 与新版，记录帧间隔、JS 提交耗时、关联进程内存和可获得的 GPU/能耗数据，标清平台和限制。
- Mac 网页与原生分别记录。补齐锁屏/睡眠/最小化桥接后在 Mac 验证；2019 Intel Mac、2014 年设备与 Apple Silicon 各自标明已测或未测。
- 每次美术迭代不等待半小时或两小时；阶段候选版本再做长时间稳定性与正常工作负载下的资源观察。

## 10. 本轮结束后再决定的事情

视觉与正常速度的旅程获认可后，再制定 M1 的完整 Focus、音乐播放、常用设置保存和桌面体验计划；竖屏构图独立设计，其他场景和创作者模板另开范围。本草案不提前替用户批准这些功能的开发顺序。
